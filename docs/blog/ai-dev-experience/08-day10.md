## 1. README 재작성

### 프롬프트 (요약)

```
Day 10 진행 프로세스 알려줘. (plan.md 기반)
```

### AI의 접근

기존 코드(Controller, application.properties)를 먼저 읽어서 실제 구현과 문서를 맞추는 방식으로 진행했다. 예를 들어 API 명세를 작성할 때 임의로 쓰지 않고 `SummarizeController.java`의 실제 validation 로직(500자 제한, 10MB 파일 크기)을 확인한 뒤 문서화했다.

**교훈:** README 같은 문서를 AI에게 맡길 때, "코드를 먼저 읽고 문서화해줘"라고 명시하지 않아도 AI가 자연스럽게 소스를 확인하는 습관을 보였다. 문서와 코드의 불일치를 방지하는 데 효과적이었다.

## 3. 스크린샷 삽입

### 작업 흐름

1. 사용자가 직접 배포 서비스를 캡처해서 `docs/images/`에 저장
2. AI가 디렉토리를 확인(`read` 도구)해서 실제 존재하는 파일명 확인
3. README에 정확한 경로로 마크다운 이미지 문법 삽입

**교훈:** 이미지 파일명을 추측하지 않고 실제 디렉토리를 먼저 확인한 것이 중요했다. 파일명 오타로 이미지가 깨지는 걸 방지.

## 4. 최종 검증

### 프롬프트 (요약)

```
최종 확인 진행
```

### AI의 검증 방식

- 문서에서 참조하는 모든 링크(`docs/plan.md`, `docs/troubleshooting/` 등)가 실제 존재하는지 디렉토리 확인
- API 명세가 실제 컨트롤러 코드와 일치하는지 대조
- 실행 명령어가 실제 프로젝트 구조와 맞는지 확인

체크리스트 형태로 결과를 정리해서 어떤 항목을 어떻게 확인했는지 투명하게 보여줬다.

| 최종 검증 | 100% | 체크리스트로 투명하게 검증 |

### 오늘 배운 것

- **문서화 작업에서 AI의 강점은 "코드와 문서의 정합성"이다.** 사람이 문서를 쓰면 코드가 바뀐 걸 놓치기 쉬운데, AI는 매번 소스를 다시 확인하는 경향이 있다.
- **이미지나 파일 경로는 추측 금지.** 실제 디렉토리를 확인하는 습관이 오류를 줄인다.
- **"최종 확인"같은 모호한 요청도 체크리스트로 구체화해서 답한다.** 검증 결과를 표로 정리하면 누락 여부를 한눈에 볼 수 있다.
