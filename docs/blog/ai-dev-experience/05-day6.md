## 2. 배포 절차 안내

### AI 역할

배포 자체는 웹 UI에서 클릭하는 작업이라 AI가 직접 실행할 수 없지만, 단계별 절차를 명확하게 안내해줬다:
- Render: repo 연결 → Docker 런타임 → 환경변수 → 배포
- Vercel: repo 연결 → Root Directory 지정 → 환경변수 → 배포

---

## 3. 배포 이슈 디버깅

### Vercel 404 문제

**상황:** 빌드 성공인데 접속하면 404.

**AI에게 전달:** 빌드 로그 + 404 에러 페이지 URL

**AI의 디버깅 과정:**
1. 빌드 로그 확인 요청 → 성공 확인
2. Framework Preset / Output Directory 설정 확인 제안
3. `Other` → `Next.js` 변경으로 해결

**교훈:** AI가 "설정 확인해봐"라고 정확한 포인트를 짚어줬다. 배포 플랫폼 설정 문제는 코드가 아니라 UI 설정이라 AI가 직접 고칠 수 없지만, 어디를 봐야 하는지 안내하는 역할은 잘 수행.

### 오늘 배운 것

- **배포는 "코드"보다 "설정"이 중요하다.** 코드는 이미 Day 5에서 준비 완료. Day 6은 플랫폼 설정과 환경변수가 핵심.
- **AI는 배포 플랫폼 UI를 직접 조작할 수 없지만**, "어디를 확인해라"를 정확히 안내해주는 것만으로도 충분히 유용하다.
- **배포 후 CORS를 `*`에서 특정 도메인으로 제한하는 건 필수.** 임시로 열어두고 잊으면 보안 구멍.
