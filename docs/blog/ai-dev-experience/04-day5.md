## 1. Dockerfile 작성

### 프롬프트 (요약)

```
Spring Boot 프로젝트용 Dockerfile 만들어줘. 멀티스테이지 빌드, JDK 21, Gradle.
```

### AI 결과

```dockerfile
FROM eclipse-temurin:21-jdk AS build
WORKDIR /app
COPY gradle gradle
COPY gradlew build.gradle settings.gradle ./
COPY src src
RUN chmod +x gradlew && ./gradlew bootJar --no-daemon

FROM eclipse-temurin:21-jre
WORKDIR /app
COPY --from=build /app/build/libs/summarize-api-0.0.1-SNAPSHOT.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

수정 없이 바로 빌드 성공.

## 2. SSL 인증서 디버깅

### 상황

Docker 컨테이너에서 Claude API 호출 시 SSL 에러 발생. AI에게 스택트레이스를 전달하며 디버깅 진행.

### AI의 디버깅 과정

1. 에러 로그 확인 → SSL 문제로 진단
2. 인증서 등록 방식 제안 (Dockerfile에서 keytool)
3. 등록했는데도 실패 → `openssl s_client`로 실제 인증서 확인 제안
4. 등록한 인증서와 실제 프록시 인증서가 다름을 발견
5. 런타임 자동 추출 방식 제안

### 최종 해결

```dockerfile
ENTRYPOINT ["sh", "-c", "echo | openssl s_client -connect api.anthropic.com:443 ... && keytool -import ... ; java -jar app.jar"]
```

### 교훈

AI가 단계적으로 디버깅을 잘 이끌었다. 특히 `openssl s_client`로 실제 인증서를 확인하자는 제안이 핵심이었다. 다만 처음부터 "등록한 인증서가 맞는지 확인"을 제안했으면 더 빨랐을 것.

### 오늘 배운 것

- **Docker 환경의 네트워크는 호스트와 다를 수 있다.** 같은 SSL 문제라도 인증서가 다를 수 있음.
- **AI에게 디버깅을 맡길 때는 에러 로그 전체를 붙여넣는 게 효과적.** 스택트레이스를 보고 정확한 위치를 짚어준다.
- **"소스 수정 없이 방안만 얘기해"라는 제약을 주면** AI가 여러 선택지를 제시해서 판단하기 좋다.
