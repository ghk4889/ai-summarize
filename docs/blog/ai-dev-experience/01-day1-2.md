# AI 활용 개발 경험 정리 — Day 1~2

## 개발 방식

이 프로젝트는 "요구사항 정의 → AI에게 구현 요청 → 검증" 루프로 진행한다. 사용 도구는 Kiro-cli(Claude 기반 코딩 에이전트)다.

핵심 원칙:
- AI에게 명확한 요구사항을 전달한다
- 생성된 코드를 맹신하지 않고 검증한다
- 삽질도 기록한다

## Day 1: 프로젝트 초기 세팅

### 프롬프트 예시

```
Spring Boot 프로젝트를 만들어줘.
- Java 21, Gradle
- POST /api/summarize 엔드포인트
- Request: { "text": "..." }
- Response: { "summary": "..." }
- 최소한의 구조로, 과설계 없이
```

### AI가 생성한 코드

```java
@RestController
@RequestMapping("/api")
public class SummarizeController {

    record SummarizeRequest(String text) {}
    record SummarizeResponse(String summary) {}

    @PostMapping("/summarize")
    public SummarizeResponse summarize(@RequestBody SummarizeRequest request) {
        return new SummarizeResponse("TODO: AI 요약 결과");
    }
}
```

Day 1에서는 stub 응답으로 API 구조만 잡았다. AI가 깔끔하게 record 기반 DTO를 생성해줬고, 별도 수정 없이 바로 사용했다.

### 효과

- 프로젝트 생성부터 첫 API 동작까지 **30분 이내**
- build.gradle 의존성 설정도 AI가 처리
- 패키지 구조 고민 시간 제로

## Day 2: Claude API 연동

### 프롬프트 예시

```
Claude Messages API를 호출하는 Service 클래스를 만들어줘.
- OkHttp 사용
- API key는 application.properties에서 읽기
- 텍스트를 받아서 요약 결과 문자열을 반환
- 에러 시 RuntimeException throw
```

### AI가 생성한 코드

```java
@Service
public class ClaudeService {

    private static final String API_URL = "https://api.anthropic.com/v1/messages";
    private static final MediaType JSON = MediaType.get("application/json");

    private final OkHttpClient client = new OkHttpClient();
    private final ObjectMapper mapper = new ObjectMapper();

    @Value("${claude.api.key}")
    private String apiKey;

    public String summarize(String text) throws Exception {
        Map<String, Object> body = Map.of(
            "model", "claude-haiku-4-5-20251001",
            "max_tokens", 1024,
            "messages", List.of(
                Map.of("role", "user", "content",
                    "Summarize the following text concisely:\n\n" + text)
            )
        );

        Request request = new Request.Builder()
            .url(API_URL)
            .post(RequestBody.create(mapper.writeValueAsString(body), JSON))
            .header("x-api-key", apiKey)
            .header("anthropic-version", "2023-06-01")
            .header("content-type", "application/json")
            .build();

        try (Response response = client.newCall(request).execute()) {
            if (!response.isSuccessful())
                throw new RuntimeException("Claude API error: " + response.code());
            Map<?, ?> result = mapper.readValue(response.body().string(), Map.class);
            return (String) ((Map<?, ?>) ((List<?>) result.get("content")).getFirst()).get("text");
        }
    }
}
```

### AI가 틀린 부분

AI가 처음 생성한 코드의 모델 ID는 `claude-3-5-haiku-20241022`였다. 이 모델은 이미 폐기되어 404 에러가 발생했다.

```
// AI가 생성한 원본 (동작 안 함)
"model", "claude-3-5-haiku-20241022"

// 직접 수정한 버전 (동작함)
"model", "claude-haiku-4-5-20251001"
```

**교훈:** AI의 학습 데이터에는 시간 제한이 있다. 외부 API의 모델 ID, 엔드포인트 URL, 인증 방식 등은 반드시 공식 문서에서 최신 정보를 확인해야 한다.

## AI 활용 시 주의점 (Day 1~2에서 배운 것)

### 1. AI가 잘하는 것
- 보일러플레이트 코드 생성 (Controller, Service, DTO)
- 라이브러리 사용법에 맞는 코드 작성 (OkHttp, Jackson)
- 프로젝트 구조 잡기
- build.gradle 의존성 설정

### 2. AI가 못하는 것
- **최신 API 상태 확인** (모델 폐기 여부, 버전 변경)
- **로컬 환경 이슈 해결** (회사망 SSL 프록시, 인증서 문제)
- **런타임 디버깅** (실제 에러 로그를 보고 원인 추적)

### 3. 효과적인 프롬프트 작성법

| 좋은 프롬프트 | 나쁜 프롬프트 |
|-------------|-------------|
| 구체적인 입출력 명시 | "API 만들어줘" |
| 사용할 라이브러리 지정 | 선택지를 AI에게 맡김 |
| 제약 조건 명시 ("과설계 없이") | 아무 조건 없이 요청 |
| 한 번에 하나의 작업 | 여러 작업을 한꺼번에 |

## 생산성 체감

| 작업 | AI 없이 (예상) | AI 활용 (실제) |
|------|--------------|--------------|
| 프로젝트 초기 세팅 | 1시간 | 15분 |
| Controller + DTO | 30분 | 5분 |
| Claude API 연동 코드 | 1시간 | 10분 |
| 디버깅 (SSL + 모델 ID) | - | 2시간 |

코드 작성 자체는 빨라졌지만, **AI가 만든 코드의 디버깅**에 시간이 들었다. 그래도 전체적으로는 확실히 빠르다.
