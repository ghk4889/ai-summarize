## Step 1: CORS 글로벌 설정 전환

Day 3에서 `@CrossOrigin` 어노테이션으로 급하게 처리했던 CORS를 `WebMvcConfigurer` 글로벌 설정으로 전환했다.

### AS-IS

```java
@RestController
@CrossOrigin(origins = "http://localhost:3000")
public class SummarizeController { ... }
```

### TO-BE

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {
    @Value("${cors.allowed-origins}")
    private String allowedOrigins;

    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/api/**")
            .allowedOrigins(allowedOrigins.split(","))
            .allowedMethods("GET", "POST");
    }
}
```

origin을 `application.properties`에서 읽도록 해서, 배포 시 프로퍼티만 바꾸면 된다. Spring Profile로 환경별 분리도 가능.

## Step 2: 에러 처리 보강

### 백엔드 — GlobalExceptionHandler

예외 종류별로 적절한 HTTP 상태코드와 한글 에러 메시지를 반환하도록 글로벌 예외 핸들러를 추가했다.

| 예외 | 상태코드 | 메시지 |
|------|---------|--------|
| ResponseStatusException | 원래 코드 (400 등) | 설정한 reason |
| RuntimeException | 502 | AI 서비스 연동 중 오류 |
| Exception | 500 | 서버 내부 오류 |

### 프론트엔드 — 에러 분기

- `TypeError` (네트워크 에러) → "서버에 연결할 수 없습니다"
- 서버 응답 에러 → 백엔드가 내려준 메시지 표시
- 기타 → 기본 에러 메시지
