# 2주 만에 AI 서비스 만들기 — Day 1~2 회고

## 프로젝트 소개

"텍스트를 넣으면 AI가 요약해주는 서비스"를 2주 안에 혼자 만들어 배포하는 프로젝트를 시작했다.

목표는 명확하다:
- 완벽한 코드가 아니라 **완성된 서비스**
- AI 도구(Kiro-cli)를 활용해 빠르게 구현
- 2주 후 실제 동작하는 서비스 + 블로그 + 포트폴리오

기술 스택은 Backend(Spring Boot + Java 21), Frontend(Next.js), AI(Claude API)로 정했다.

---

## Day 1: Backend 기본 세팅

### 한 일
- Spring Boot 프로젝트 생성 (Gradle, Java 21)
- `POST /api/summarize` 엔드포인트 구현
- GitHub repository 생성 및 첫 push

### 느낀 점

Spring Boot 프로젝트 초기 세팅은 익숙한 작업이지만, Kiro-cli를 활용하니 보일러플레이트 코드 작성 시간이 확실히 줄었다. Controller, DTO 구조를 잡는 데 10분도 안 걸렸다.

"완벽주의 금지" 원칙을 의식적으로 지켰다. 평소라면 패키지 구조를 고민하고, 예외 처리 전략을 설계하고, DTO 변환 레이어를 만들었을 텐데 — 그냥 Controller 하나에 record DTO 두 개로 시작했다.

```java
record SummarizeRequest(String text) {}
record SummarizeResponse(String summary) {}
```

이게 끝이다. 과설계 없이 동작하는 코드부터 만들었다.

## Day 2: Claude API 연동

### 한 일
- Claude Messages API 연동
- OkHttp로 HTTP 클라이언트 구현
- AI 요약 응답 반환 성공
- Controller → Service 분리

### 삽질 기록

Day 2는 순탄하지 않았다. 두 가지 이슈를 만났다.

**1) SSL trustAnchors 오류**

회사 내부망의 SSL 프록시 때문에 Claude API 호출 시 SSL 인증서 검증이 실패했다. `trustAnchors parameter must be non-empty` 에러가 발생했는데, 원인은 두 가지였다:

- 회사 프록시의 루트 CA 인증서가 Java cacerts에 없었음
- keytool로 인증서를 등록하는 과정에서 cacerts 파일의 비밀번호 상태가 변경됨

해결: 프록시 루트 CA를 cacerts에 등록하고, JVM 옵션에 `-Djavax.net.ssl.trustStorePassword=changeit`을 추가했다.

**2) Claude 모델 ID 404 오류**

AI가 생성한 코드에 `claude-3-5-haiku-20241022`라는 이미 폐기된 모델 ID가 들어있었다. 현재 유효한 `claude-haiku-4-5-20251001`로 변경하니 해결됐다.

이건 AI 도구를 쓸 때 주의할 점이다. AI의 학습 데이터는 과거 시점이므로, **외부 API의 최신 상태는 직접 확인해야 한다.**

### 교훈

- AI가 생성한 코드도 맹신하면 안 된다. 특히 외부 API 관련 코드는 공식 문서와 대조 필수.
- 회사망 환경에서의 SSL 이슈는 한 번 해결하면 끝이지만, 처음 만나면 시간을 많이 잡아먹는다. 문서화해두길 잘했다.
- "삽질도 기록이다." 트러블슈팅 문서를 바로 작성해두니 나중에 같은 문제를 만났을 때 즉시 해결할 수 있다.
