# 2주 만에 AI 서비스 만들기 — Day 7 회고

## 오늘의 목표

- 배포 환경 버그 확인
- 입력 길이 제한 / validation 추가
- 에러 응답 정리 + 타임아웃 처리

---

## Step 1: 배포 환경 점검

배포된 서비스에서 치명적 버그는 없었다. 잠재적 문제 2가지 확인:
- OkHttp 타임아웃 미설정 (무한 대기 가능)
- 입력 길이 제한 없음 (토큰 초과 / 비용 폭증 가능)

---

## Step 2: 입력 길이 제한

### 백엔드

500자 초과 시 400 에러 반환:

```java
if (request.text().length() > 500) {
    throw new ResponseStatusException(BAD_REQUEST, "text must not exceed 500 characters");
}
```

### 프론트엔드

- textarea에 `maxLength={500}` 속성 추가
- 글자 수 카운터 표시 (400자 초과 시 빨간색)

---

## Step 3: 에러 응답 정리 + 타임아웃

### OkHttp 타임아웃 설정

```java
private final OkHttpClient client = new OkHttpClient.Builder()
    .connectTimeout(Duration.ofSeconds(10))
    .readTimeout(Duration.ofSeconds(30))
    .build();
```

### 에러 응답 계층 정리

| 상태코드 | 발생 시점 | 메시지 |
|---------|----------|--------|
| 400 | 입력 검증 실패 | text must not be empty / exceed 500 characters |
| 502 | Claude API 에러 응답 | AI 서비스 연동 중 오류 |
| 504 | Claude API 타임아웃 | AI 서비스 응답 시간 초과 |
| 500 | 기타 예외 | 서버 내부 오류 |

## 삽질: Next.js Turbopack 캐시 문제

로컬에서 `npm run dev` 실행 시 `Can't resolve 'tailwindcss'` 에러 발생. Day 5에서 루트 `package-lock.json`을 삭제한 후 `.next` 캐시에 잘못된 resolve 경로가 남아있었다.

해결: `.next` 폴더 삭제 후 재실행.

**교훈:** 빌드 관련 설정을 변경한 후에는 캐시를 삭제하고 확인하는 습관이 필요하다.
