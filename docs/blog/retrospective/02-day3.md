## Step 1: 백엔드 프롬프트 개선

기존 프롬프트는 `"Summarize the following text concisely"` — 단순 문자열 응답이었다. 프로젝트 목표가 summary / keyPoints / actions 구조이므로, system 프롬프트를 새로 설계했다.

### AS-IS

```
(system 프롬프트 없음, user 메시지에 직접 포함)

"Summarize the following text concisely:\n\n" + text
```

→ 단순 문자열 응답 반환

### TO-BE

```
[system]
You are a document summarizer. Analyze the given text and respond with ONLY a JSON object in this exact format:
{"summary":"A concise 2-3 sentence summary","keyPoints":["key point 1","key point 2","key point 3"],"actions":["action item 1","action item 2"]}
Rules: summary is a brief overview. keyPoints are the most important facts (3-5 items). actions are actionable next steps if any (0-3 items, empty array if none). Respond with ONLY the JSON, no markdown or explanation.

[user]
(텍스트 원문만 전달)
```

→ 구조화된 JSON 응답 반환

변경 사항:
- system 프롬프트로 JSON 형식 응답 유도
- `SummarizeResult` record 생성 (summary, keyPoints, actions)
- Controller 응답 타입 변경

### 삽질: Claude가 마크다운으로 감싸는 문제

"JSON만 응답하라"고 했는데 Claude가 `` ```json `` 코드블록으로 감싸서 반환했다. Jackson 파싱에서 `JsonParseException` 발생.

해결: 파싱 전에 backtick 코드블록을 strip하는 방어 코드 추가. LLM 출력은 100% 보장이 안 되므로 방어 코드는 필수라는 걸 배웠다.

## Step 5: 프론트-백 연동

### 삽질: CORS 에러

브라우저에서 `localhost:3000` → `localhost:8080` 요청 시 `Failed to fetch` 발생. 예상했던 CORS 문제.

해결: Controller에 `@CrossOrigin(origins = "http://localhost:3000")` 추가. 배포 시에는 글로벌 설정으로 전환 예정.

연동 후 정상 동작 확인. 텍스트 입력 → 요약 결과 카드 표시까지 전체 플로우 완성.
