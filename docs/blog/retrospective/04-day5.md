## Step 1: Dockerfile 작성

멀티스테이지 빌드로 구성:
- Stage 1 (JDK 21): Gradle 빌드 → bootJar 생성
- Stage 2 (JRE 21): JAR만 복사해서 실행 (이미지 크기 최소화)

### 삽질: SSL 인증서 문제 (다시)

Docker 컨테이너에서 Claude API 호출 시 SSL 핸드셰이크 실패. Day 2에서 겪었던 회사 프록시 문제가 Docker 환경에서도 재현됐다.

**1차 시도:** `.devcontainer/root_ca.crt`를 Dockerfile에서 등록 → 실패. 확인해보니 등록한 인증서와 실제 프록시 인증서가 달랐다.

**2차 시도:** 런타임에 자동으로 프록시 인증서를 추출해서 등록하는 방식으로 전환.

```dockerfile
ENTRYPOINT ["sh", "-c", "echo | openssl s_client -connect api.anthropic.com:443 2>/dev/null | openssl x509 -out /tmp/proxy_ca.crt && keytool -import ... ; java -jar app.jar"]
```

컨테이너 시작 시 자동으로 현재 네트워크의 프록시 인증서를 추출/등록한다. 프록시가 바뀌어도 자동 대응.

## Step 2: application-prod.properties

환경변수 주입 방식으로 prod 설정 분리:

```properties
server.port=8080
claude.api.key=${CLAUDE_API_KEY}
cors.allowed-origins=${CORS_ALLOWED_ORIGINS}
```

Spring Profile 오버라이드 구조: `application.properties`(기본값) → `application-prod.properties`(덮어쓰기)

### 실무 권장 방안

실무에서는 `application.properties`에 공통 설정만 두고, 환경별 값은 `application-local.properties`, `application-dev.properties`, `application-prod.properties`로 완전히 분리하는 게 일반적이다. 오버라이드 방식은 "최종 적용값이 뭔지" 추적이 어렵고, 실수로 로컬 값이 운영에 적용되는 사고를 방지하기 어렵기 때문.

### 채택하지 않은 이유

이 프로젝트는 환경이 local/prod 2개뿐이고 설정도 3줄이라, 오버라이드 방식으로 충분하다. 완전 분리는 과설계.
